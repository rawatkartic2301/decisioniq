# DecisionIQ: Fine-Tuning Module (`finetune/`)

This directory provides end-to-end domain adaptation tooling for DecisionIQ:
1. **Embedding Model Domain Fine-Tuning** (Sentence-Transformers + Contrastive MultipleNegativesRankingLoss)
2. **LoRA / PEFT Instruction Fine-Tuning** (Hugging Face Transformers + PEFT + TRL)

---

## 1. Embedding Model Fine-Tuning

### Overview
Enterprise vocabulary often causes off-the-shelf embedding models (such as `all-MiniLM-L6-v2`) to collapse semantic distances between distinct internal policies (e.g., *Privilege Leave carry-forward* vs *Casual Leave lapse rules*). We fine-tune the dense embedding representation using **MultipleNegativesRankingLoss** with in-batch hard negatives sampled from versioned or departmental policies.

### Triplet Dataset
Synthetic triplets are generated by `finetune/generate_triplets.py`:
- **Query**: Domain question (e.g. *"What is the maximum allowed overtime hours per week?"*)
- **Positive**: Exact chunk containing the clause (`doc_overtime_2024#chunk_2`)
- **Hard Negative**: Adjacent clause from the same department or outdated version (`doc_overtime_2022#chunk_1`)

### Reproduction & Benchmark
Run the CPU-friendly adaptation workflow:
```bash
python finetune/finetune_embeddings.py
```
Measured results are automatically logged to [`finetune/EMBEDDING_BENCHMARK.md`](./EMBEDDING_BENCHMARK.md).

## 2. LoRA / PEFT Instruction Fine-Tuning

### Target Models & Hyperparameters
Lightweight open-weights architectures (~0.5B to 1B parameters) are targeted for cost-effective enterprise hosting:
- **Default Base Model**: `Qwen/Qwen2.5-0.5B-Instruct` (or `meta-llama/Llama-3.2-1B`)
- **LoRA Rank ($r$)**: `8`
- **LoRA Alpha ($\alpha$)**: `16`
- **Target Modules**: `["q_proj", "v_proj"]`
- **Dropout**: `0.05`
- **Task Type**: `CAUSAL_LM`
- **Trainable Parameter Ratio**: ~0.45% of total base weights

### SFT Dataset Format
Generated by `finetune/generate_sft_dataset.py` in Alpaca / ChatML schema:
```json
{
  "instruction": "You are DecisionIQ, an enterprise assistant. Answer using the provided context, citing sources in format [Doc: <source_doc>#<chunk_id>]...",
  "input": "Context: [Doc: hr_leave_policy_v2_2024.md#doc_leave_2024#chunk_1]: ...\nQuestion: What is the carry-forward limit?",
  "output": "Based on the official enterprise policy [Doc: hr_leave_policy_v2_2024.md#doc_leave_2024#chunk_1], employees may carry forward up to 45 days..."
}
```

### Running the Script
- **Dry-run / CPU Verification (local laptop)**:
  ```bash
  python finetune/lora_instruction_tune.py --dry-run
  ```
- **Full GPU Execution (Google Colab / Cloud GPU)**:
  ```bash
  python finetune/lora_instruction_tune.py --no-dry-run --epochs 3 --batch-size 4 --lr 2e-4
  ```

## 3. Honest Engineering Analysis & Trade-Offs

| Decision Angle | Fine-Tuning Approach | Production Trade-off & Honest Limitation |
| :--- | :--- | :--- |
| **Embeddings vs Reranker** | Contrastive Embedding Adaptation | Adapting embeddings improves dense Recall@k by ~15-20%, but **Cross-Encoder reranking** provides higher precision (nDCG@3) at inference time without risk of vector space drift. |
| **Instruction Tuning vs RAG** | LoRA Instruction Fine-Tuning | Fine-tuning small LLMs (<1B params) on domain Q&A **teaches formatting and citation syntax**, but **does NOT reliably memorize factual enterprise knowledge**. When facts change (e.g. policy version 2.0), the model must be retrained or it hallucinates. RAG with dynamic prompt grounding is strictly superior for factual compliance. |
| **Dataset Size Threshold** | LoRA on Small Corpus (<50 pairs) | On small datasets (<100 samples), fine-tuning risks catastrophic forgetting of safety and general instruction-following capabilities. SFT should only be used when 500+ verified multi-turn enterprise traces are available. |
